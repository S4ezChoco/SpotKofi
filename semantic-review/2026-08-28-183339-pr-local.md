# Songlink external-link flow replacing provider playback

The working-tree change replaces the in-app music catalog and player with a link-only Odesli/Songlink flow. `OdesliLinkRepository` validates a pasted web URL and constructs an official Songlink page, while Search and Library expose recent resolutions and hand page URLs to Android’s external `ACTION_VIEW` flow. The active working-tree source contains no Audius/YouTube provider wiring, stream extraction, queue, or in-app player surface. The **confirmed** delivery state is not yet shippable: the required link-only files are untracked, the index still stages the retired provider/player graph, and the Home-to-Search navigation can leave the bottom bar on the wrong tab.

Watch for: **confirmed, blocking** repository-state mismatches that can omit the new implementation or reintroduce Audius/YouTube/Media3 code; **confirmed, high** bottom-tab desynchronization after either Home CTA or route restoration; and **confirmed, medium** acceptance of arbitrary cleartext or untrusted hosts as “official” links.

**Blocking issues are present.**

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed:** The checked-out runtime graph is link-only. `AppContainer` owns `OdesliLinkRepository`; the repository returns page URLs and never performs an API call or creates a media source, and the UI has no active player or queue route.

**Confirmed:** The local change set has two incompatible representations. The working tree deletes the old player files and contains new link-only files, but those new files are untracked while the index still contains Audius, YouTube, Media3, and ExoPlayer additions. A build of the checkout therefore does not prove that the eventual commit or PR contains the intended graph.

**Confirmed:** The external handoff stays outside the app, but its trust contract is only scheme-and-host presence. Any HTTP or HTTPS host can become the “Original link,” and the launcher repeats that permissive check instead of enforcing an official-provider policy.

**Confirmed:** Home/Search/Library are present as coherent screens, but tab selection is stored separately from the navigation destination. The Home search buttons do not update that state, so the primary CTA can land on Search with Home selected and make a subsequent Search-tab tap a no-op.

**Confirmed:** Recent links are process-scoped and the repository has no behavioral tests. The Library copy makes the session boundary explicit, but process recreation, external-launch failure, and route synchronization are not covered by automated checks.

### Staged provider/player graph can be committed back

**Severity: BLOCKER · Confidence: confirmed.** The checked-out source is clean of the retired graph: `AppContainer.kt` now exposes only `linkRepository`, while the old player/provider files are absent from the working tree. The index tells a different story. `git diff --cached` still contains `app/src/main/java/com/spotkofi/app/data/remote/AudiusApi.kt`, `AudiusDto.kt`, `AudiusMapper.kt`, `YouTubeApi.kt`, `YouTubeDto.kt`, `YouTubeMapper.kt`, `data/repository/AudiusMusicRepository.kt`, `YouTubeMusicRepository.kt`, `player/ExoPlayerController.kt`, `player/YouTubePlayerSurface.kt`, and the staged player changes in `NowPlayingScreen.kt` and `PlayerController.kt`. It also stages `YOUTUBE_DATA_API_KEY` and Media3 dependencies in `app/build.gradle.kts` and `gradle/libs.versions.toml`.

A debug assemble of the working tree cannot detect this because the files are deleted from the checkout. The staged version must be reconciled before shipping; otherwise the exact requirement to remove Audius, the other retired provider, protected-media extraction, and fake playback is not guaranteed.

### Link-only production boundary is untracked

**Severity: BLOCKER · Confidence: confirmed.** `app/src/main/java/com/spotkofi/app/core/AppContainer.kt` imports `LinkRepository` and `OdesliLinkRepository`, and `SpotKofiApp.kt` calls `launchExternalLink`, but all three implementation files show as `??` rather than tracked changes: `app/src/main/java/com/spotkofi/app/data/repository/LinkRepository.kt`, `OdesliLinkRepository.kt`, and `app/src/main/java/com/spotkofi/app/ui/ExternalLinkLauncher.kt`. The current checkout assembles only because those untracked files are present. A patch generated from `git diff main`, or a commit that stages only the tracked deletions/modifications, will omit them and leave the submitted project uncompilable.

### Home CTA and restored routes can desynchronize the bottom bar

**Severity: HIGH · Confidence: confirmed.** `SpotKofiApp.kt:76` keeps `activeTab` as independent `remember` state and passes it to the bottom bar at `:176`. The Home route wires both search CTAs at `:134` directly to `navController.switchTab(TopLevelDestination.Search)` without setting `activeTab`. That produces a Search destination with Home still highlighted; because `isOnTabRoot(Search)` then sees the Search route at `:183`, tapping the already-visible Search tab does nothing and cannot repair the stale selection. Back navigation has the inverse problem, and the unsaved `remember` state is also likely to reset to Home when a restored NavController comes back on Search or Library after recreation.

Derive the selected tab from `currentBackStackEntry` or centralize all route changes through a function that updates both route and selection. This keeps Home’s CTA, bottom navigation, back, and configuration restoration on one source of truth.

### The URL gate trusts arbitrary web destinations

**Severity: MEDIUM · Confidence: confirmed.** `OdesliLinkRepository.kt:70-73` accepts both `http` and `https` whenever `Uri.host` is nonblank; it does not restrict the source to known music-service domains, reject credentials/other URL ambiguity, or mark the result as untrusted. The generated `OfficialLink(platformId = "source", url = sourceUrl)` is rendered as the original link and is sent to `ExternalLinkLauncher.kt:10-16`, whose duplicate check has the same any-host/HTTP policy. Thus a pasted `http://` page or phishing host is presented alongside the “official” Songlink path and can be opened through an installed app.

The implementation does not scrape the page or treat the URL as a stream, but that does not make the original destination trustworthy. Either enforce HTTPS plus an approved-provider/resolver allowlist, or make arbitrary originals explicitly untrusted and require a confirmation before the `ACTION_VIEW` handoff. Keep the resolver URL canonical and official even when the source is not.

### Chooser availability is not preflighted

**Severity: MEDIUM · Confidence: likely.** `ExternalLinkLauncher.kt:14-22` catches `ActivityNotFoundException` and `SecurityException`, but returns `true` immediately after `startActivity(Intent.createChooser(...))` without checking whether the target web intent has a handler. On a device with no browser/provider, the system chooser can still be launched with no usable target, so the caller may suppress its “No browser is available” snackbar despite the link being unusable. Preflight the target intent with `resolveActivity` before creating the chooser and retain the exception handling for the race between the check and launch.

### Recent links are intentionally non-durable

**Severity: LOW · Confidence: confirmed.** `OdesliLinkRepository.kt:21` stores at most 20 resolutions in a process-local `MutableStateFlow`; there is no DataStore, Room, or backup representation. `LibraryScreen.kt` explicitly tells users that resolved links appear “during this session.” If “Library” is intended to survive process death, that expectation is not met; either preserve the session-only wording as the contract or add deliberate durable storage with a policy for raw URL/query data.

### Build passes, but behavior has no automated guard

**Severity: MEDIUM · Confidence: confirmed.** `:app:testDebugUnitTest` and `:app:assembleDebug` pass for the current checkout, but there are no unit or instrumentation test files. The successful build does not exercise the private URL normalization path, external intent availability, the Home CTA/tab mismatch, or process recreation. Add focused tests around those contracts before treating the assemble result as sufficient validation.

`lintDebug` remains red on `app/src/main/res/values/themes.xml:11` (`windowLayoutInDisplayCutoutMode` requires API 27 while minSdk is 26). That file is outside this change, so the lint error is not attributed to this review; it does mean the repository-wide lint task is not currently green.

### OkHttp has no active link-flow caller

**Severity: LOW · Confidence: confirmed.** The working-tree build adds `implementation(libs.okhttp)` in `app/build.gradle.kts` and defines it in `gradle/libs.versions.toml`, but the active source has no `OkHttpClient`, request, or catalog API implementation. The new repository is synchronous URL construction, not a network client. Remove the direct dependency until it is needed, or make the intended network behavior part of a separate, reviewed change rather than carrying an unused provider-era dependency into the link-only build.
